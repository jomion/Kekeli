KEKELI — Livraison du 19 septembre 2026 (suite) — Comptes liés (vues parent/enseignant)
========================================================================================

Ceci complète le point 3 de la livraison précédente ("Compte parent ajouté par un
enseignant" / "Compte parent ou enseignant ajouté par une autorité pédagogique"),
qui restait en attente de clarification. Vos réponses :
  - Oui, la vue parent liée a l'accès parent COMPLET (paiements, accès, horaires
    compris) — pas une vue restreinte.
  - Pour ajouter un enfant, le compte utilise le même parcours "Inscrire un enfant"
    que n'importe quel parent — pas de recherche/liaison vers un élève existant.

CE QUI A ÉTÉ FAIT
-------------------------------------------------------------------
Un enseignant peut désormais activer une "vue parent" liée à son propre compte
(même identifiant de connexion, même e-mail, sans se déconnecter). Sur son tableau
de bord, une carte "🔀 Vue parent" propose un bouton "Activer" ; une fois activée,
elle devient un lien "Basculer" qui l'emmène directement sur le tableau de bord
parent habituel. Un bandeau discret en haut de la page parent rappelle qu'il s'agit
de la vue liée, avec un lien "← Retourner à mon espace" pour revenir à l'espace
enseignant.

Une autorité pédagogique peut, de la même façon, activer une vue parent ET/OU une
vue enseignant liées à son compte, indépendamment l'une de l'autre (nouvelle
section "Vues liées" sur sa page d'accueil).

Dans les deux cas, la vue liée est à 100% la vraie page existante (parent ou
enseignant) — mêmes fonctionnalités, y compris les paiements côté parent — et pour
ajouter un enfant, on utilise exactement le même bouton "Inscrire un enfant" que
tout parent utilise déjà. Rien de nouveau à apprendre.

Techniquement, activer une vue liée n'ajoute qu'une ligne dans la table
correspondante (parents ou enseignants), sans jamais toucher au rôle principal du
compte ni à aucune autre donnée — aucun risque pour le reste du site.

BONUS : UN BUG PRÉEXISTANT CORRIGÉ AU PASSAGE
-------------------------------------------------------------------
En construisant cette fonctionnalité, une vérification en base a révélé que la
table des enseignants n'avait jamais reçu l'autorisation de base pour créer ou
modifier sa propre fiche (seule la "règle" existait, pas la "permission" sous-
jacente qui la rend effective). Concrètement, cela empêchait déjà, avant même
cette livraison :
  - l'inscription normale d'un nouvel enseignant sur le site (l'étape finale
    échouait silencieusement côté base de données) ;
  - la page "Compléter mon profil" pour un enseignant (école, circonscription,
    zone pédagogique).
C'est corrigé : les enseignants peuvent maintenant s'inscrire et compléter leur
profil normalement, comme les parents ont toujours pu le faire.

Fichiers modifiés : js/auth-utilisateur.js, js/pages/autorite-bienvenue.js,
js/pages/enseignant-tableau-de-bord.js, js/pages/parent-tableau-de-bord.js.

Base de données (Supabase, appliqué immédiatement) : correction des permissions
manquantes (GRANT) sur la table enseignants (création et modification de sa propre
fiche), pour authenticated et anon — aucune nouvelle table, aucune policy RLS
modifiée.

Vérifications faites avant cette livraison : node --check sur les 4 fichiers JS
modifiés ; permissions vérifiées une à une en base après correction
(has_table_privilege) ; mcp__Supabase__get_advisors (sécurité) relancé après la
migration — aucune nouvelle alerte, zéro erreur, seulement les avertissements
préexistants déjà présents sur tout le projet.
