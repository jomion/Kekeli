KEKELI — Livraison : cause enfin trouvée pour les devoirs invisibles côté enseignant
================================================================================

1. Le devoir rendu par l'élève n'est ENFIN plus invisible pour l'enseignant
------------------------------------------------------------------------
Ce signalement était revenu trois fois malgré des vérifications déjà faites
côté base de données (contenu bien enregistré, notification correcte,
permissions correctes). Cette fois, la cause a été trouvée en dehors de la
base : dans la page "Devoirs & notes" de l'enseignant, la liste des classes
ET des élèves affichés ne se construisait qu'à partir du "suivi" élève par
élève (un parent demande le suivi d'un enseignant précis, l'enseignant
accepte) — alors qu'un enseignant peut aussi avoir une classe qui lui est
attribuée directement par l'administration (Gestion administrative), ce qui
lui donne bien le droit de tout voir/corriger dans cette classe, mais que
cette page ignorait complètement pour choisir QUI afficher.

Concrètement, avec une classe de 4 élèves attribuée à un enseignant, si un
seul de ces 4 élèves avait fait l'objet d'un suivi individuel accepté, les 3
autres élèves de la même classe (et donc leurs devoirs rendus, pourtant bien
enregistrés et bien notifiés) restaient invisibles dans le panneau de
gestion — pas de ligne, pas de contenu, alors que l'enseignant avait bien le
droit de les corriger. D'où l'impression exacte que vous décriviez : la
notification arrive, mais jamais le contenu.

Corrigé : une classe attribuée directement à l'enseignant affiche
maintenant TOUS ses élèves dans le panneau de gestion des devoirs, comme
c'est déjà le cas côté administration — le suivi individuel reste utilisé
uniquement pour les classes atteintes uniquement par ce biais (aucune
classe attribuée). Vérifié directement en base sur votre propre enseignant
de test : sa classe (CM2) compte 4 élèves, dont un seul était visible avant
ce correctif.

Fichier modifié : js/pages/enseignant-devoirs-notes.js

2. Le nombre de tâches d'un palier revient après son nom, entre parenthèses
------------------------------------------------------------------------
Le titre d'un palier affichait le nombre total de tâches tout devant, avant
le nom du palier (ex. "12 tâches — Azɔ̀ví — 8/12 réussies (67%)"). Sur votre
demande, ce total revient après le nom, entre parenthèses, sans toucher à
l'affichage de la progression juste à côté : "Azɔ̀ví (12 tâches) — 8/12
réussies (67%)". Même changement pour un palier encore verrouillé.

Fichier modifié : js/pages/eleve-seance.js

3. Bouton "Classes" de la page d'accueil : reste sur la page au lieu de l'ouvrir
------------------------------------------------------------------------
Dans le menu du haut de la page d'accueil, le lien "Classes" ouvrait la
vraie page de navigation des classes (celle utilisée une fois connecté). Il
défile désormais simplement vers la section "Nos classes" de la page
d'accueil elle-même — exactement comme le fait déjà le lien "Paliers" juste
à côté. Vérifié dans un navigateur réel : le clic reste sur la page
d'accueil et affiche bien la section.

Fichier modifié : index.html

Aucune migration dans cette livraison (les 3 correctifs sont entièrement
frontend).
